## Hard-won gotchas (cost me two wasted 10-min runs)
- **monkeypatch does NOT survive spawn.** evaluate_system(jobs>1) must use
  spawn. To patch across workers, define a real SUBCLASS in an importable
  module and reassign `obj.__class__`; pickling stores module+qualname so the
  child imports it.
- **a CLASS attribute set at runtime is NOT pickled** -> spawned workers saw
  donor=None and silently filled nothing (result: exactly 0.0000 diff, which
  looks like "no effect" but is really "patch never ran"). Use an INSTANCE
  attribute. ALWAYS assert the patch actually fired (counter > 0) before
  believing a null result.
- Cheap smoke run (48 boards, jobs=1) before the 800-board run catches both.

BRILL EXPRESSION LANGUAGE (parsed 3515/3515 = 100%):
  Grammar: or/and/not/parens, `|` and `or` BOTH mean OR (case-insensitive
  keywords — Brill emits uppercase `AND` sometimes), comparisons, calls.
  Two parser bugs worth remembering:
   - function-call branch must fall through to arith(), else
     `suitpoints('C') > 12` leaves the `>` unconsumed.
   - keywords are case-insensitive (`AND` / `and`).

DSL FORMAT (canonical parser = bid.eval_vs_dds.load_decision_net_dsl):
  block form  RULE id: / CALL: / PRIORITY: / CONDITION: key op value
  one-line    RULE id PRIORITY n ACTION call WHEN c1, c2
  ops: == != >= <= > < in not_in.  Conditions are ANDed; unknown key => False.
  CALL strings: "1NT" not "1N"; P->PASS is only for parse, str(Pass)="PASS".
  Negative PRIORITY is fine.

AUCTION SEAT SEMANTICS (worked out from the data — non-obvious):
  Brill anchors every position on OUR turn, so the call immediately before
  the hole is always an OPPONENT's, the one before that PARTNER's:
    ``      we open            -> is_opening==True
    1H      LHO opened, we act -> opp_last_call=='1H'
    1H-P    partner opened, RHO passed, we respond
    1H-1S   partner opened, RHO overcalled, we act
  opp_last_call only tracks BIDs (never passes): a pass gives 'NONE'.
  Adding partner_last_call/my_last_call=='NONE' cuts lint shadowing 380->75.

TWO TRAPS THAT CAUSE SILENT WRONGNESS (both hit, both fixed):
  1. `Xlongest` / `bestsuit(X)` need a FEATURE-TO-FEATURE compare
     (club_len >= longest_suit_len). The DSL RHS must be a CONSTANT, so the
     RHS parses as a string -> TypeError at match time. MUST be dropped.
  2. `explicitshape == '4=3=3=3'` vs repo `shape_pattern` (digits SORTED):
     4=3=3=3 and 3=3=3=4 both sort to 4333, so mapping alone RELAXES the
     rule. Must also pin spade_len/heart_len/diamond_len/club_len.
