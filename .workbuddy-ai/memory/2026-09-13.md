## Brill fidelity measured against the live engine (§6.44)

**`/bid` is the key endpoint** — `GET /bid?hand=<PBN S.H.D.C>&ctx=1H-P&seat=S&dealer=N`
returns Brill's actual call + the winning `requires`. Also `details=true`
adds an `analysis` array (winning rule name, priority, requires per call).
`/inferresponses` needs explicit `bids=`; `/bids` returns 34 opening defs.

New harness `research/brill_live_check.py` (caches to /tmp/brill_live.json).
Dealer pinned N → hand to act is N+len(calls) = N/E/S. 2,528 comparisons
(316 positions × 8 random hands): **top-1 69.3%, top-3 70.3%, anywhere
70.3%, silent 0%**. top-1 ≈ anywhere ⇒ misses are total (call absent, not
outranked) ⇒ confirms "drop, never relax".

**Attribution reorders §6.42** (which was row-count weighted):
verdicts = 72-79% of blockers by impact vs 23% by row count. `penalty` 7%
(biggest single), `game` 5.6%, `cansacrifice` 3.6%, `makessense` 3%.
Conversely longest-suit = +78 rows but 0.4% impact; `loserlevel` = +226 rows
but 1 occurrence in 2,528. Don't do those first.

**The wall is structural**: `/bid` analysis labels these `(GameEval)` and
prints sampled hands — `cansacrifice`/`*_compgame` evaluate a DEAL, not a
hand. No hand feature can reproduce them.

**Semantics pinned empirically** (don't guess these):
- `clublongest` is NON-strict (ties count): 4=3=2=4 with 13 HCP opens 1C.
  The "safe" strict guess would have been wrong.
- `ruleof21` = hcp + two longest >= **20** (not 21): 11 HCP 5-4-3-1 opens
  1S, 5-3-3-2 passes. UNRESOLVED anomaly: 5-2-2-4 (sum 20) passes.
- Hand builder gotcha: fill suits with LOWEST cards then upgrade to honors,
  else you build 30+ HCP hands and every probe returns 2C.

## Misses split three ways (§6.46)

§6.44 only sees dropped-clause misses. Full breakdown of 750 misses:
- 429 (57%) blocked only by verdicts → unreachable
- **239 (32%) rule WAS emitted but did not fire** → §6.44 blind to these.
  Dropping a clause makes a rule MORE permissive, never less, so these are
  WRONG translations, not missing ones. 158/239 contain an approximate atom.
- 65 (9%) mixed · 17 (2%) no rule emitted (6X-X redoubles)

**`X_points -> X_hcp` is provably wrong**: at 1C-2N, 3C needs `C_points>=7`
and Brill bids it with AQT96 clubs = 6 HCP.

Clean sweep at 1H-1N (4H top-priority, `H_points>=11 and H>=4`), 20 hands:
min HCP to bid 4H = len5→9, len6→7, len7→6, len4→never. Fits
**suit_hcp + 2*(suit_len-4)** on 20/20. BUT contradicts the C_points case.
**Not applied** — the fitted mapping is more permissive → would relax.

**CRITICAL gotcha: `/bid`'s `requires` is an explanation HINT, not a
verified firing condition.** First probe returned `H >= 6` for a 3-heart
hand. Usually right, never ground truth. Use `/bid?details=true` → the
`analysis` array names the winning rule explicitly. That's how to settle
X_points.

Also: probes at non-top-priority positions are confounded — a higher-pri
rule winning means the target call not firing tells you nothing.

## dsl-design.md review (§6.47) — verdict: mostly already built

Evaluated `research/dsl-design.md` (semantic/intent DSL: bidding operators,
ACTION(intent,target,constraints), encode() slots, semantic state, bid
equivalence classes). Verdict: **do not rewrite the DSL.** Adopt 2 of 12 sections.

Facts established:
- **§2/§6/§7 already exist**: `bid/protocol.py` ProtocolStep(op_type,
  trigger_sequence, target_feature, call_mapping) IS ACTION + ENCODE.
  ProtocolOpType = SHOW/ASK/COMMAND/TRANSFER/ENCODE/CONCEAL/AMBIGUATE/POOL.
  11 convention factories (Stayman, Jacoby, Texas, Blackwood, Drury, Michaels,
  Unusual2NT, Cappelletti, Smolen, Gambling).
- **The "invent conventions" payoff already exists**: `convention_search.py`
  hill-climbs protocol space (retarget feature = semantic mutation; swap
  call_mapping / shift ranges = encoding mutation). This IS the doc's
  "semantic and encoding layers evolve separately".
- **§4's premise is false here.** Doc assumes search branches over ~30 legal
  calls. It doesn't: `DecisionNet.actions()` returns only calls from *matched*
  rules. The compression is already banked by phi(s).
- **§8 is genuinely missing** and is the one real win: no `agreed_trump`,
  `forcing_status`, `captain`, `convention_context` in features.py. Only
  `our_fit_shown` (bool), `support_in_partner_suit`, `partner_last_bid_strain`.
  §6.41 already measured this as THE blocker for RKCB/Gerber/GSF.

**Latent bug found**: `ProtocolStep.generate_rules()` builds conditions ONLY
from `target_feature`/`val`. `op_type` is cosmetic (description string only)
and **`trigger_sequence` is never compiled into any condition** — so Stayman
compiles to bare `heart_len>=4 -> 2H` and Blackwood to `ace_count==2 -> 5H`,
both firing on ANY auction. Confirmed no protocol rule reaches a shipped
system (grep: stayman|blackwood|jacoby|texas|smolen|cappelletti = 0 hits in
improved_system.dsl / champion_system.dsl; those are 75 and 90 rules).

**Convention search output is degenerate**: `data/conventions/search_report.json`
— the single "accepted" invention is Jacoby retargeted to `king_count` with
mapping {True: 2H, False: 2H}, i.e. "always bid 2H". train gain 451,
val_delta 25, **z = 0.12** yet verdict "escalate". Caused by the missing
trigger_sequence (no auction context ⇒ nonsense is searchable) plus no
significance gate.

**Why not the rest**: 72–79% of the brill.dsl fidelity gap (by impact) is
Brill's deal-level verdicts (`penalty`, `loserlevel`, suit quality) — hand
*evaluation* primitives, not encoding. A semantic/encoding layer cannot fix
those. Adding a second language also means a second parser for lint_dsl.py,
translator.py, eval_vs_dds, brill_to_dsl and the 20-file web/ JS port.

Recommended order: (1) add agreed_trump/forcing to features.py; (2) compile
trigger_sequence into auction conditions; (3) optional INTENT: annotation;
(4) do NOT adopt WHEN/IF/DO + ENCODE as the on-disk format.
