## The Brill API is latency-bound — 7x harvest speedup (big win)

- Measured 16 concurrent `client.bid` calls: **1.66x / 3.66x / 6.96x at
  2 / 4 / 8 workers**, 0 errors, ~0.65 s/request sequential.
- **Gotcha that produced 12/16 errors:** pinning `seat="N"` while varying
  `ctx` length asks for an impossible combination and Brill errors. The seat
  to act is `dealer + len(ctx) mod 4`.
- **`build_deals` is NOT prefix-stable** — `build_deals(50)[:50] !=
  build_deals(100)[:50]`. So you cannot shard by asking for more boards;
  every shard must use the identical `--boards` and `--seed`.
- Added `--shard K/N` to `research/brill_remote_eval.py`. It keeps the
  GLOBAL board index (`indexed = list(enumerate(all_deals))[k::n]`) because
  `seed_board(seed, i)` must match the unsharded run.
- Bug I introduced and fixed: the checkpoint print used the global index, so
  a shard looked like it was skipping checkpoints.
- Killed the 5-hour sequential harvest (pid 49121, 3,916 traces) after
  backing up its cache; 6 shards reused that cache so those requests were
  not re-issued. **1.10 boards/s vs 0.154 sequential = 7.1x.**
  Cache key is the full URL (hand+ctx+seat+dealer+vul) — verified no
  collision risk from sharing it.
- `research/brill_merge_traces.py` added: merges shards, **checks they were
  actually disjoint** (the failure mode is a shard run with a different
  `--boards`, which still emits plausible traces), dedupes on
  `(deal, ctx, seat)`, reports truncated auctions.

## Where the misses are — and why reweighting cannot fix it (§6.65)

`research/brill_miss_stakes.py` (splits held-out by DEAL, not trace):

| Brill's call | n | agreement | share of miss mass |
|---|---|---|---|
| PASS | 5384 | **96.5%** | 10.9% |
| level 1 | 1276 | 92.6% | 5.5% |
| level 2 | 900 | **49.8%** | 26.4% |
| level 3 (game) | 597 | **22.3%** | 27.1% |
| level 4+ (slam) | 480 | **24.2%** | 21.3% |

- **84% of disagreement mass is on level-2+ calls = 25% of the data.** The
  model aces passing and opening; it misses game/slam 4 times out of 5.
- **Fix fails monotonically.** `--stakes-boost` 0/1/2 -> **-0.10 / -1.41 /
  -2.20** IMP/board; paired vs unweighted **-1.31 (t -3.90)** and
  **-2.10 (t -5.56)**. Contested boards 184 -> 212 -> 217, contested IMP
  +1.23 -> -2.49 -> -3.28.
- Mechanism: weighting by stakes makes it bid MORE, dragging it into
  contested auctions it then loses. Pass-outs unchanged (3), so not the
  pass-out story.
- Conclusion: the concentration is **genuine difficulty, not class
  imbalance**. Forcing the call does not create the missing signal.
- Scoreboard of "fix objective/representation" attempts: routing features
  +0.4pp/~0 IMP; pass-cap -1.91; DAgger +0.5pp/0 IMP; depth tuning 0
  (already optimal); stakes weighting -1.31 to -2.10. **Only more data has
  ever moved the number.**

### Surgical follow-up — refuted in an informative direction (§6.65)

Unrestricted boosting damaged contested almost entirely (+1.23 -> -2.49)
while the weakness is uncontested, so added `--stakes-scope uncontested`
(amplifies only where `opponents_bid` is false; 41% of traces).

| variant | IMP/board | contested | uncontested |
|---|---|---|---|
| no boost | **-0.10** | +1.23 | -0.69 |
| boost 1 all | -1.41 | -2.49 | -0.82 |
| boost 1 uncontested | -0.79 | +0.63 | -1.42 |
| boost 2 uncontested | -0.86 | +0.39 | -1.44 |

Paired vs unweighted: -0.687 (t -2.70), -0.767 (t -2.91). Contested is
**preserved** (-0.45 t -1.04) but uncontested is significantly **worse**
(-0.79 t -2.53) — the opposite of the prediction. It is not too timid about
game; push it to bid more in a clean auction and it bids game on hands that
should not. **What is missing at game level is signal, not willingness.**
Six interventions, only data has ever moved the number.
