## Brill `realsolid` recovered by probing (status.md §6.53)

Previous session's probe failed (Brill doubled all 28). The fix: **read the
`requires` field, not the bid.** At `ctx=1C seat=E` the realsolid rule has
HIGHER priority than the takeout double, so Brill's `/bid?...` reply is a
clean 1-bit readout — `requires` mentions `realsolid` iff the predicate held.

Fitted table (350/350 on held-out random hands), with A and K both mandatory:

| honours beyond A-K | min length |
| --- | --- |
| AKQJ | 6 |
| AKQT | 7 |
| AKQ | 8 |
| AKJ (ten irrelevant) | 9 |
| AK / AKT | never |

NOT "AKQ and 6+" — that over-bids. Ten only counts with Q and without J.
Spot-card height irrelevant.

Implemented as `x_realsolid` booleans in `features.py` (inside the per-suit
honour loop) + `realsolid('X')` mapping in `brill_to_dsl.translate_call`.
Rules 1,676 -> 1,932 (+256). Locked by
`test_realsolid_matches_brills_measured_table`.

## Lesson: coverage != fidelity

Fidelity was **unchanged** (4,488/6,320 = 71.0% before and after). Not a bug:
`realsolid and losers == 1` occurs in 1 in 33,333 random hands -> 0.19
expected firings in the sample. The biggest atom on the board bought ~0
measured fidelity. When ranking atoms by clause count, also price how often
the clause can actually fire.

## `research/brill_atom_value.py` — prices atoms before you implement them

Ranks untranslated Brill atoms by an UPPER BOUND on fidelity gain, not clause
count. For each DNF clause blocked by exactly one atom it translates the rest
and Monte-Carlos how often the co-conditions hold at that position.

    python3 research/brill_atom_value.py --hands 200 --top 20
    python3 research/brill_atom_value.py --calibrate   # sanity-check itself

**Calibration passes:** `--calibrate` pretends realsolid is still untranslated
and prices it at 0.20/6,320; the measured gain was 0.

**Headline result: `trump()` (190 clauses, now #1 on the board) prices at
0.20 — do NOT implement it.** All 190 trump rows carry a `losers` gate, so
they inherit the same throttle as realsolid. Also priced ~0: solid, twosuited,
Fit, IsGoodSuit, Balanced, singlesuited, CombinedHcpMin, TwiceRebiddable.

Everything with real headroom (monsterslam / monstergrand / CanBid7NT ~510,
slammish ~231) is a deal-level verdict = the §6.48 structural wall.

=> **At the hand-feature level the Brill conversion is finished.** 71.1% is
not a plateau that more atom recovery lifts. Next real move is either accept

## Brill API connector built (`src/bid/brill`, docs/BRILL_CONNECTOR.md)

Typed, stdlib-only client for `brillservice.aalborgdata.dk` covering all 25
swagger paths. `client.py` / `models.py` / `convert.py` / `play.py` + CLI
(`python3 -m bid.brill ...`). 68 offline tests.

**The published OpenAPI doc declares NO response schemas** — `/dd` is typed as
`Void`. All dataclasses were recovered by calling the live service. Keep
undocumented keys on `.raw`.

**`/play` has three undocumented constraints** — recovered from its 400 bodies,
which are unusually informative (always read `HTTPError.read()`, not the code):

- `played` is **separator-free** (`"S7SA"`). A comma -> *"has odd length"*.
- `hand` must be the **original 13 cards**; Brill subtracts `played` itself
  (*"has 12 cards (expected exactly 13)"*).
- Card 1 = **declarer's LHO**, then REAL play order: the trick winner leads the
  next trick, so it is NOT a repeating N-E-S-W cycle. Brill names the seat it
  assigned each position to in its error — that is how the ordering was found.
- Zero cards played -> *"use the /lead endpoint instead"* (raised locally).

`PlayState` (`play.py`) owns that ordering + follow-suit legality + trick
accounting, and works with a local engine too.

**Validation:** a full 52-card board drove against the live service with zero
400s, finishing NS 12 tricks = exactly `/dd`'s number for that deal. Because
Brill rejects any card whose seat disagrees with its own assignment, a clean
52-card run PROVES PlayState's leader sequence matches the service's.

Useful for §6.53-style atom fitting: `requires` scraping is now repeatable and
cacheable (`cache_path=`), plus `/dd` gives the deal-level ground truth that
§6.48 says is the only route past 71.1%.

## Distillation pipeline built (`research/brill_distill.py`, §6.58)

Traces (position -> Brill's call) -> `BridgeFeatures.extract_all` (same 121-key
vector `DecisionNet.actions()` uses) -> repo's own `ID3DecisionTree` ->
`id3_tree_to_rules` (its guard mechanism pins each tree to its position) ->
`export_dsl`. Round-trips through `load_decision_net_dsl`. No unpublished
atoms, no tree crawl.

**Grouping is the one real design decision**: ID3 splits only on numeric/bool,
so it cannot partition on call IDENTITY (`opp_last_call` is a string). Pilot
(2,442 traces = 1,954 train / 488 held out), held-out agreement with Brill:

configurations on; use `--folds 5`, se ~= sd/sqrt(5)):

| grouping | rules | 5-fold CV |
| --- | --- | --- |
| none (one global tree) | 203 | **69.8%** (sd 1.4) |
| is_opening | 229 | 68.9% (sd 1.6) |
| auction_len x level x strain | 349 | 65.4% (sd 1.6) |
| auction_len | 516 | 64.0% (sd 3.0) |
